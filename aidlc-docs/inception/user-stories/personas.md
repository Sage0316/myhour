# 하꾸 Personas

## Product Persona Principle

하꾸의 핵심 사용자는 이미 기록 습관이 완성된 사람이 아니다. 기록하고 싶은 마음은 있지만 바쁜 일상, 입력 마찰, 잦은 중단 때문에 꾸준히 기록하지 못하는 사람이다. 제품은 사용자의 성실함을 요구하기보다 짧은 기록을 안전하게 모으고 하루가 끝났을 때 다시 보고 싶은 결과물로 정리해야 한다.

## Persona 1: 윤서, 바쁜 일상 기록자

**Story role key**: Journal User  
**Role**: Primary product persona  
**Archetype**: 기록 의지는 있지만 별도의 일기 시간을 꾸준히 확보하기 어려운 모바일 사용자

### Snapshot

- 출퇴근, 식사, 산책, 약속 사이의 짧은 틈에 휴대폰을 사용한다.
- 하루에 세 번에서 여섯 번 정도 사진, 짧은 영상, 음성 또는 한두 문장의 메모를 남기고 싶다.
- 기록 자체보다 하루가 지나간 뒤 “오늘이 이런 날이었구나”라고 돌아보는 경험에 가치를 느낀다.
- iOS 또는 Android 홈 화면 PWA를 사용하며 네트워크가 불안정한 상황도 흔하다.
- 결과물을 가끔 저장하거나 가까운 사람에게 보여줄 수 있지만 공개 피드 운영이나 전문 편집은 원하지 않는다.

### Representative Quote

> “꾸미는 건 앱이 해주고, 나는 오늘을 놓치지만 않으면 좋겠어요.”

### Core Job to Be Done

하루가 무심히 지나가 버리기 전에 짧은 순간들을 부담 없이 붙잡고, 밤에는 별도의 편집 노동 없이 다시 보고 싶은 하나의 기록으로 남기고 싶다.

### Goals

1. 알림을 받았을 때 흐름을 끊지 않고 몇 초 안에 기록한다.
2. 사진, 영상, 음성, 메모가 앱을 닫아도 사라지지 않는다고 믿는다.
3. 기록 시각과 하루 경계가 자신의 생활 리듬에 맞게 정리되기를 원한다.
4. 복잡한 설정 없이 하루 마감을 시작하고 진행 상황을 이해한다.
5. 완성된 세로 영상을 즉시 확인하고 나중에 아카이브에서 다시 본다.
6. AI와 Push가 사용하는 데이터 범위를 직접 이해하고 통제한다.

### Behaviors

- 주로 한 손으로 사용하며 긴 문장을 입력하기보다 사진이나 짧은 음성을 선호한다.
- 알림을 바로 처리하지 못하고 지나치는 경우가 있으므로 죄책감을 주는 표현에 민감하다.
- 앱이 추천하는 기본값을 그대로 사용하는 경우가 많다.
- 생성 작업 중 화면을 잠그거나 다른 앱으로 이동할 수 있다.
- 하루가 자정을 넘긴 뒤 끝나는 날도 있어 달력 날짜와 체감하는 하루가 다를 수 있다.
- 저장 실패나 권한 문제를 기술 용어 없이 해결할 수 있기를 기대한다.

### Frustrations and Anxieties

- 저장된 줄 알았던 기록이나 영상이 앱 재실행 후 사라지는 것
- 같은 시간대의 기록이 덮어써지거나 잘못된 날짜에 들어가는 것
- 눌러도 결과에 영향을 주지 않는 가짜 설정과 불명확한 성공 표시
- 영상 생성이 멈춘 것인지 진행 중인지 알 수 없는 것
- 백업 파일에 사진과 영상이 실제로 포함됐는지 확인할 수 없는 것
- AI 사용을 위해 비밀키나 개인정보 전송 범위를 스스로 판단해야 하는 것
- 중복 알림, 늦은 알림, 지나치게 재촉하는 알림

### Trust and Accessibility Needs

- 영속 저장이 끝난 뒤에만 성공으로 표시한다.
- 실패해도 기존 기록과 아카이브는 그대로 보존한다.
- AI는 선택 기능이며 명시적으로 동의한 최소 텍스트만 전송한다.
- 아이콘 버튼에는 읽을 수 있는 이름이 있고 필수 동작은 길게 누르기에만 의존하지 않는다.
- 저장공간, 권한, 기기 기능 부족을 원인과 다음 행동으로 나눠 안내한다.
- 진행 중인 장시간 작업은 단계, 진행률, 취소 결과를 명확히 보여준다.

### Primary Journey

1. 윤서는 오전에 알림을 받고 사진 한 장과 짧은 캡션을 저장한다.
2. 오후에는 같은 시간 슬롯에 짧은 음성 기록을 추가한다.
3. 이동 중 네트워크가 끊겨도 두 기록은 기기에 저장된다.
4. 밤에 추천 기본값으로 하루 마감을 시작한다.
5. 앱은 준비, 인코딩, 저장 단계를 보여주고 결과를 아카이브에 영속화한다.
6. 윤서는 방금 생성된 날짜 카드를 열어 영상을 확인한다.
7. 며칠 뒤 같은 아카이브를 다시 열거나 전체 기록을 백업한다.

### Success Signals

- 첫 기록을 설명서 없이 완료한다.
- 대표 흐름인 기록, 마감, 아카이브, 재생을 중단 없이 완료한다.
- 앱 재시작 후 원본과 생성 영상이 모두 재생된다.
- 알림을 놓쳐도 앱 사용을 포기하게 만드는 압박을 느끼지 않는다.
- 기본값만으로 만족할 수 있는 결과를 얻고 고급 편집 도구를 찾지 않는다.
- 백업, 삭제, 복원 왕복 후 논리 데이터와 미디어가 동일하다.

### Product Decision Rules

1. 빠른 기록과 안전한 저장이 꾸미기 옵션보다 우선한다.
2. 기본 경로는 한 손 사용과 최소 입력을 기준으로 한다.
3. 성공 표시는 실제 영속화 상태와 일치해야 한다.
4. 사용자가 선택하지 않은 네트워크 전송은 발생하지 않는다.
5. AI, Push, 고화질 생성이 실패해도 로컬 기록 핵심 흐름은 유지한다.
6. 선택지가 기능적으로 연결되지 않았다면 구현될 때까지 노출하지 않는다.

## Persona 2: 민준, 데이터 주권형 기록 보관자

**Story role key**: Journal User  
**Role**: Secondary product persona  
**Archetype**: 편리함보다 기록의 장기 보존, 개인정보 통제, 복구 가능성을 더 중요하게 보는 사용자

### Snapshot

- 개인 기록을 외부 계정이나 클라우드에 기본 저장하는 것을 꺼린다.
- AI 기능은 전송 필드와 보존 범위를 이해한 뒤 선택적으로 사용한다.
- 기기 교체나 브라우저 데이터 삭제 전에 완전한 백업을 만들고 싶다.
- 화려한 결과보다 원본 보존과 재현 가능한 복원을 더 중요하게 평가한다.

### Core Job to Be Done

내 기록이 어디에 저장되고 무엇이 외부로 전송되는지 통제하면서, 기기를 잃거나 앱이 업데이트되어도 내가 소유한 파일로 전체 기록을 복구하고 싶다.

### Goals and Needs

- 모든 원본과 생성 결과를 포함한 검증 가능한 백업
- 가져오기 전 스키마, 크기, 경로, 해시 검증
- 실패 시 기존 데이터를 보존하는 원자적 복원
- 로컬 데이터와 서버 측 설치 데이터의 명확한 삭제
- AI와 Push 데이터의 최소 수집, 보존 기간, 삭제 방법에 대한 설명
- 마이그레이션 결과와 복구 불가능한 항목에 대한 투명한 보고

### Success Signals

- 내보내기 파일만으로 빈 설치에 전체 기록을 복원할 수 있다.
- 같은 백업을 반복해서 가져와도 중복이 생기지 않는다.
- AI를 사용하지 않아도 핵심 기록과 영상 생성 흐름을 완료한다.
- 개인정보 안내만 읽고 저장 위치와 외부 전송 범위를 설명할 수 있다.

## Persona 3: 도현, 1인 베타 운영자

**Story role key**: Beta Operator  
**Role**: Supporting stakeholder persona  
**Archetype**: 소규모 공개 베타의 앱, Cloudflare 서비스, 비밀키, 배포와 장애 대응을 함께 맡는 개발 운영자

### Snapshot

- 전담 보안, SRE, 고객지원 조직 없이 제한된 시간으로 베타를 운영한다.
- 보호된 Git 브랜치와 CI/CD를 통해 변경을 배포한다.
- 사용자 콘텐츠 자체를 보지 않고 빌드 버전, 스키마 버전, 오류 코드와 이벤트 ID로 문제를 진단해야 한다.
- 반복 가능한 자동화와 짧고 명확한 런북을 선호한다.

### Core Job to Be Done

사용자 콘텐츠를 열람하거나 매번 수동으로 서버를 확인하지 않고도 남용, 장애, 중복 알림을 탐지하고 안전하게 배포하거나 이전 버전으로 되돌리고 싶다.

### Goals

- AI와 Push 엔드포인트 남용 및 공급자 비밀키 노출 방지
- 미리보기와 프로덕션의 데이터, 비밀키, 허용 출처와 권한 분리
- 인증 실패, 속도 제한, AI 오류, Push 실패에 대한 구조화 로그와 경보
- 설치별 기능 토큰 및 사용량 한도의 회수
- 검증된 빌드의 자동 배포와 재현 가능한 롤백

### Frustrations and Risks

- 브라우저 번들이나 로그에 포함된 공급자 비밀키
- 인증 없이 호출 가능한 테스트 또는 변경 API
- 재현되지 않는 중복 Push와 시간대 경계 오류
- 미리보기와 프로덕션이 같은 상태 저장소를 공유하는 구성
- 테스트 근거와 롤백 절차가 없는 릴리스
- 민감정보가 포함되거나 검색할 수 없는 로그

### Success Signals

- 프로덕션 배포가 보호된 브랜치와 승인된 자동화에서만 실행된다.
- 사용자 콘텐츠 없이 구조화 이벤트만으로 장애 범위를 파악한다.
- 토큰 회수, 비밀키 교체, 장애 확인과 롤백을 런북대로 재현한다.
- CI가 타입, 린트, 테스트, 빌드와 공급망 검사를 차단 조건으로 실행한다.

## Anti-Personas and Scope Guardrails

### 전문 영상 편집자

타임라인 편집, 세밀한 트랜지션, 다중 오디오 트랙, 색 보정이 핵심인 사용자는 현재 목표가 아니다. 하꾸는 편집 도구가 아니라 자동 하루 기록 도구다.

### 공개 피드 중심 크리에이터

팔로워, 좋아요, 댓글, 성장 분석과 바이럴 배포가 핵심인 사용자는 현재 목표가 아니다. 공유는 선택적 결과 내보내기이며 제품의 중심은 개인 회고다.

### 실시간 다기기 협업 사용자

여러 사람이 같은 저널을 편집하거나 모든 기기에서 즉시 동기화해야 하는 사용자는 현재 공개 베타 범위가 아니다. 현재 핵심은 로컬 우선 저장과 사용자 소유 백업이다.

## Implementation Priority Derived from Personas

1. 영속 저장과 마이그레이션 신뢰성
2. 짧고 실패 안전한 캡처 흐름
3. 기본값 중심의 마감과 모바일 영상 생성
4. 아카이브 재생과 완전한 백업·복원
5. 선택적이며 최소 데이터만 사용하는 AI
6. 정확하고 중복 없는 Push
7. 운영 자동화, 관측 가능성, 보안 강화
