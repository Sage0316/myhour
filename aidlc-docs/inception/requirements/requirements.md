## 3. 목표와 비목표

### 목표

1. 기록과 아카이브가 시간 슬롯 경계에서 누락되거나 잘못 묶이지 않게 한다.
2. 사진, 영상, 음성, 생성 결과를 앱 재시작 뒤에도 안전하게 유지한다.
3. 백업 파일 하나로 설정, 기록, 아카이브, 모든 미디어를 검증 가능하게 복원한다.
4. AI와 Push 기능에서 브라우저 비밀키 노출과 무인증 공개 엔드포인트를 제거한다.
5. iOS와 Android PWA에서 영상 생성과 핵심 사용자 여정을 공개 베타 수준으로 검증한다.
6. 반복 가능한 CI/CD, 보안 검사, 배포 및 롤백 절차를 마련한다.

### 비목표

- 데스크톱 브라우저의 공식 지원
- 다중 사용자 협업, 소셜 공유, 유료 결제
- 계정 기반 클라우드 동기화
- Resiliency Baseline이 요구하는 다중 리전·고가용성 아키텍처
- 기본값으로 1080×1920 이상 영상을 강제하는 것

## 4. 사용자

### Journal User

하루 동안 사진, 영상, 음성, 메모를 기록하고 하루가 끝날 때 하나의 영상과 아카이브를 만들고 싶은 모바일 사용자다.

### Beta Operator

Cloudflare Worker, 비밀키, Push 일정, 오류 로그, 배포와 롤백을 관리하는 운영자다. 사용자 콘텐츠를 열람할 필요 없이 서비스 상태와 보안 이벤트를 확인할 수 있어야 한다.

## 5. 기능 요구사항

### FR-001 안정적인 기록·슬롯 식별

모든 기록은 안정적인 `id`, `slotId`, `capturedAt`을 가져야 한다. 같은 슬롯에 여러 기록을 저장할 수 있어야 하며, 렌더링 키와 데이터 조회는 배열 인덱스나 현재 시각에 의존해서는 안 된다.

수용 기준:

- 13:17에 만든 기록은 13:00 슬롯에 포함된다.
- 같은 슬롯의 여러 기록이 서로 덮어쓰지 않는다.
- 자정을 넘는 기록도 사용자의 로컬 날짜와 시간대 기준으로 정확히 분류된다.
- 기존 인덱스 기반 데이터는 결정적이고 멱등적인 ID로 마이그레이션된다.

### FR-002 트랜잭션 기반 미디어 저장

사진, 영상, 음성, 생성 영상은 타입이 지정된 IndexedDB 저장소를 통해 영속화한다. `localStorage`에는 작은 메타데이터와 설정만 둔다. 쓰기 실패는 호출자까지 전달하며 UI는 영속화가 완료되기 전에 성공으로 표시하지 않는다.

수용 기준:

- 앱을 종료하고 다시 열어도 저장된 미디어가 재생된다.
- 메타데이터 쓰기가 실패하면 고아 Blob이 정리된다.
- 저장공간 부족 시 원본을 보존하고 사용자에게 필요한 정리 조치를 안내한다.
- 캡처 전에 파일 크기·종류·가용 저장공간 한도를 검사한다.

### FR-003 버전 기반 데이터 마이그레이션

앱 스키마 버전을 도입하고 순서가 보장된 멱등 마이그레이션을 제공한다. 마이그레이션은 가능한 기존 데이터를 보존하며 복구할 수 없는 미디어 참조를 사용자에게 보고한다.

수용 기준:

- 같은 마이그레이션을 반복 실행해도 결과가 바뀌지 않는다.
- 실패 시 원본 데이터를 삭제하거나 부분 변환 상태로 확정하지 않는다.
- 마이그레이션 결과에 변환, 건너뜀, 누락 미디어 수가 표시된다.

### FR-004 완전한 백업과 원자적 복원

백업은 설정, 현재 기록, 아카이브, 감독 메타데이터, 원본 미디어, 생성 미디어를 포함하는 버전형 컨테이너여야 한다. 매니페스트에는 스키마 버전, 파일 목록, 크기, 해시가 포함되어야 한다.

수용 기준:

- `export → delete local data → import` 후 논리 데이터와 미디어 해시가 동일하다.
- 가져오기 전에 스키마, 타입, 크기, 해시를 검증한다.
- 변조된 파일, 경로 순회 항목, 압축 폭탄 위험이 있는 백업을 거부한다.
- 복원은 원자적이며 실패 시 기존 데이터를 그대로 유지한다.
- UI가 예상 백업 크기, 진행률, 누락·충돌 경고를 보여준다.
- 동일 백업을 재가져와도 중복 데이터가 생기지 않는다.

### FR-005 정확한 하루 마감

마감 화면에는 실제 동작하는 제어만 유지한다. 무드와 알림 시점은 결과와 일정에 반영한다. 이모지, 차분함, 출력 비율, 수동 BGM 등 1차 범위에서 연결하지 않는 제어는 숨긴다.

수용 기준:

- 표시되는 기록 수와 비어 있는 상태가 실제 데이터와 일치한다.
- 마감 완료는 필수 저장과 아카이브 커밋이 성공한 뒤에만 표시된다.
- 숨겨진 옵션은 접근성 트리와 키보드 탐색에도 노출되지 않는다.

### FR-006 마감 후 아카이브 인계

마감이 성공하면 아카이브 경로로 이동하고 방금 생성한 날짜 카드를 자동으로 연다. 아카이브 ID로 생성 영상을 다시 조회한다.

수용 기준:

- 새로 생성된 항목이 즉시 열리고 재생 가능하다.
- 새로고침 뒤에도 같은 아카이브를 직접 열 수 있다.
- 사용하지 않는 `HomeWrapped`, `setWrapped`, 임시 `videoUrl` 상태를 제거한다.
- 생성된 Object URL은 사용 종료 시 해제한다.

### FR-007 모바일 영상 생성 안정성

기본 출력은 720×1280과 보수적인 비트레이트를 사용한다. 고화질은 기기 기능과 저장공간을 확인한 뒤 선택적으로 제공한다. 시작 전에 코덱, 저장공간, 오디오, 캔버스 기능을 검사한다.

수용 기준:

- 대표 iOS 및 Android PWA 기기에서 사진·영상·음성이 섞인 하루 영상을 생성한다.
- 준비, 인코딩, 저장 단계를 구분한 진행률과 취소 기능을 제공한다.
- 취소와 실패 시 타이머, 스트림, Object URL, 임시 Blob을 정리한다.
- 실패해도 원본 기록과 기존 아카이브는 보존된다.
- 생성 영상은 앱 재시작 뒤에도 재생된다.

### FR-008 보호된 AI 프록시

브라우저에 장기 비밀키를 저장하지 않는다. Cloudflare Worker가 공급자 비밀키를 소유하며 베타 설치 단위의 회수 가능한 접근 토큰을 사용한다.

수용 기준:

- 요청·응답 스키마, 본문 크기, 타임아웃, 모델 허용 목록, 설치별·IP별 요청 한도를 적용한다.
- 사진, 영상, 음성 원본은 AI 공급자에게 전송하지 않고 사용자가 입력한 텍스트와 명시적으로 선택한 캡션만 전송한다.
- 첫 사용 전에 데이터 전송 내용을 설명하고 명시적 동의를 받는다.
- AI 출력은 스키마 검증 후 사용하며 실패 시 로컬 규칙 기반 결과로 대체한다.
- 클라이언트 번들, 로그, 오류 메시지에 공급자 비밀키가 나타나지 않는다.

### FR-009 정확하고 멱등적인 Push 일정

일정에는 설치 ID, 일정 버전, 슬롯 간격, 알림 시점, 시간대, 마지막 전송 상태를 포함한다. 자정 경계를 포함해 `before`, `exact`, `both`를 정확히 계산한다.

수용 기준:

- 60분 및 120분 간격에서 예정된 알림 시각이 정확하다.
- 각 전송은 설치·일정 버전·슬롯·알림 종류로 만든 멱등 키를 사용한다.
- 재시도나 Cron 중첩으로 중복 알림이 발생하지 않는다.
- 만료 구독과 존재하지 않는 일정은 안전하게 정리한다.
- 시간대나 설정 변경 시 기존 일정을 갱신하며 이전 일정이 남지 않는다.

### FR-010 보호된 Push API

Push Worker의 모든 변경 요청은 인증된 설치 기능 토큰 또는 동등한 서명 검증을 요구한다. 리소스 소유권은 서버에서 확인한다.

수용 기준:

- 허용 출처를 명시한 CORS, 요청 스키마, 크기 제한, 속도 제한을 적용한다.
- 사용자가 제공한 임의 엔드포인트 호스트로 서버가 요청하지 않는다.
- 다른 설치의 구독이나 일정을 읽거나 수정할 수 없다.
- 오류 응답은 내부 구현과 비밀 정보를 노출하지 않는다.

### FR-011 공개 베타 운영 환경

미리보기와 프로덕션 Worker는 KV, 비밀키, 허용 출처를 분리한다. 검토된 소스와 고정된 의존성으로만 배포한다.

수용 기준:

- 배포물에 빌드·스키마 버전을 기록한다.
- AI·Push 토큰과 사용량 한도를 설치 단위로 회수할 수 있다.
- 운영 문서에 비밀키 교체, 장애 확인, 이전 버전 롤백 절차가 있다.
- 프로덕션 배포는 보호된 브랜치와 승인된 워크플로에서만 실행된다.

### FR-012 자동화 품질 게이트

Pull Request와 보호된 브랜치에 CI를 적용한다.

수용 기준:

- 정확한 잠금 파일 설치, TypeScript 검사, 경고 0개의 Oxlint, 단위 테스트, 속성 기반 테스트, Worker 테스트, 백업 테스트, 프로덕션 빌드를 실행한다.
- 핵심 기록·마감·복원 흐름을 브라우저 테스트로 검증한다.
- iOS PWA와 Android PWA 대표 기기 매트릭스를 릴리스 체크리스트에 포함한다.
- 배포 액션은 고정된 버전 또는 커밋을 사용한다.

### FR-013 제품·개인정보 문서

README에 지원 플랫폼, 로컬 우선 저장, 권한, AI 전송 범위, 데이터 보존, 백업·삭제, 알려진 한계를 설명한다. 번들 미디어의 라이선스와 출처를 기록한다.

## 6. 비기능 요구사항

### NFR-001 보안

- 외부 통신은 TLS를 사용하고 Cloudflare 관리형 암호화와 최소 권한을 적용한다.
- CSP, HSTS, `X-Content-Type-Options`, 프레임 제한, Referrer Policy를 설정한다. 현재 호스팅에서 필요한 헤더를 설정할 수 없다면 지원 가능한 호스팅으로 이전한다.
- 모든 신뢰 경계에서 요청을 검증하고 인증, 소유권 검증, 속도 제한을 적용한다.
- 비밀키, 토큰, 사용자 콘텐츠, 전체 Push 엔드포인트를 로그에 남기지 않는다.
- 잠금 파일, 의존성 검사, 비밀 탐지, SBOM, 고정된 CI 액션을 적용한다.

### NFR-002 개인정보 보호

- 사용자 콘텐츠는 기본적으로 기기에만 저장한다.
- AI 전송은 명시적으로 동의한 텍스트 필드로 최소화한다.
- Push 저장 데이터는 전달에 필요한 최소 필드로 제한하고 사용자가 전체 로컬·서버 데이터를 삭제할 수 있게 한다.

### NFR-003 신뢰성

- 데이터 변경은 원자적이거나 복구 가능해야 한다.
- 외부 호출에는 타임아웃과 안전한 폴백을 둔다.
- 재시도 가능한 작업은 멱등적이어야 한다.
- 영속화가 확인되기 전에 성공 상태를 표시하지 않는다.

### NFR-004 성능

- 기본 영상 출력은 720×1280을 사용하며 긴 동기 작업으로 UI를 멈추지 않는다.
- 초기 JavaScript 예산은 gzip 기준 120KB 이하를 목표로 하고 BGM·미디어 도구는 필요할 때 로드한다.
- 대용량 작업은 진행률과 취소를 제공한다.

### NFR-005 호환성

- iOS 16.4 이상 홈 화면 PWA와 최신 Android Chrome PWA를 공식 지원한다.
- 지원되지 않는 기능은 시작 전에 감지하고 사용 가능한 대안을 설명한다.
- 모든 저장 스키마 변경은 이전 버전 데이터 마이그레이션을 포함한다.

### NFR-006 관측 가능성

- Worker 로그는 구조화하고 중앙에서 검색 가능하게 보관한다.
- 인증 실패, 속도 제한 급증, Push 실패율, AI 공급자 오류율에 경보를 둔다.
- 보안 이벤트 로그는 공개 베타 기준 90일 보관을 목표로 한다.

### NFR-007 유지보수성

- 영속화, 마이그레이션, 미디어, AI, Push 모듈의 경계를 명확히 한다.
- 죽은 상태와 사용하지 않는 코드를 제거한다.
- 린트 경고 0개를 유지하고 운영·복구 절차를 코드와 함께 버전 관리한다.

### NFR-008 접근성

- 변경된 화면의 버튼, 대화상자, 진행 상태에 의미 있는 이름과 키보드 포커스를 제공한다.
- 아이콘 전용 버튼은 접근 가능한 이름을 가져야 한다.
- 필수 기능을 길게 누르기에만 의존하지 않는다.

## 7. 속성 기반 테스트 요구사항

부분 적용 규칙은 PBT-02, PBT-03, PBT-07, PBT-08, PBT-09이다.

- 프레임워크는 기존 Vite·TypeScript 환경과 통합 가능한 Vitest와 fast-check를 사용한다.
- 설정, 세션, 기록, 아카이브, 미디어 매니페스트, 백업을 위한 재사용 가능한 생성기를 둔다.
- 일정 계산은 순서, 중복 없음, 슬롯 경계, 시간대 변환 불변성을 검사한다.
- 직렬화·역직렬화, 마이그레이션, 내보내기·가져오기는 왕복 속성을 검사한다.
- 실패 사례는 자동 축소하고 재현 seed와 축소된 입력을 CI 결과에 남긴다.

## 11. 완료 정의

- 모든 P0·P1 요구사항에 자동화 또는 수동 검증 근거가 있다.
- 기존 데이터 마이그레이션과 완전 백업·복원 왕복이 통과한다.
- 선택한 속성 기반 테스트가 CI에서 통과하고 실패 재현 정보를 남긴다.
- AI와 Push Worker의 인증, 검증, 속도 제한, 비밀키 관리가 배포 환경에서 확인된다.
- 대표 iOS와 Android PWA에서 기록, 마감, 생성, 재생, 백업·복원 스모크 테스트가 통과한다.
- 보호된 브랜치에서 CI와 승인된 배포·롤백 절차가 작동한다.
