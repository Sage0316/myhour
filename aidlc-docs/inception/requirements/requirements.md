# 하꾸 iOS 앱스토어 출시 요구사항

최종 갱신: 2026-10-28

## 의도 분석

- **사용자 요청**: "이제 앱스토어 작업 시작하자" — 하꾸를 아이폰 앱스토어에 유료로 출시
- **요청 유형**: Migration + New Feature (웹앱을 iOS 앱으로 감싸고 유료 결제를 새로 붙임)
- **범위**: System-wide (앱 코드, AI Worker, 빌드·배포 파이프라인, 앱스토어 등록)
- **복잡도**: Complex (애플 심사, 결제, 서버 권한, 클라우드 빌드가 함께 얽힘)
- **요구사항 깊이**: Standard — 질문 14개에 대한 답(`requirement-verification-questions.md`)을 반영

## 기능 요구사항

### FR-1 iOS 앱 패키징
- 지금 React 앱을 Capacitor로 iOS 앱에 넣는다. 화면 코드는 그대로 재사용한다.
- 앱 파일은 앱 안에 포함한다 (원격 웹사이트를 불러오지 않는다).
- 앱용 빌드는 `/myhour/` 경로 없이 동작해야 한다.
- 서비스워커 없이도 모든 기능이 동작해야 한다.

### FR-2 유료 결제
- 상품 2개: 한달권 자동 갱신 구독, 15일권 1회 이용권. 3일 무료 체험은 한달권의 첫 구독 혜택(애플 계정당 1회)으로 붙인다.
- 결제는 애플 인앱결제만 쓴다. 외부 결제 링크·안내를 넣지 않는다.
- 결제 상태 확인은 RevenueCat으로 한다.
- "구매 복원" 버튼을 제공한다 (애플 필수).
- 유료 화면(페이월)에 가격, 기간, 자동 갱신 여부, 해지 방법, 이용약관·개인정보처리방침 링크를 표시한다 (애플 필수).

### FR-3 유료 기능 잠금
- 이용권이 없으면 "영상 만들기"와 "AI에게 연출 맡기기"에서 페이월을 띄운다.
- 기록하기, 오늘, 아카이브 보기, "영상 없이 마감", 이미 만든 영상 보기·저장은 이용권 없이도 된다.
- AI 서버는 요청마다 이용권이 유효한지 서버 쪽에서 확인한다. 앱만 막고 서버가 열려 있으면 안 된다.
- 기존 연출 횟수 제한(날짜당 4회, 하루 8회)은 유료 사용자에게도 그대로 적용한다.

### FR-4 기록 시간 알림
- 설정한 시작 시간·간격·알림 시점에 맞춰 폰 자체 예약 알림을 건다.
- 설정을 바꾸면 예약을 다시 건다. 하루 마감 후 그날 남은 알림은 취소한다.
- iOS 예약 알림 개수 상한(64개)을 넘지 않게 앞으로 며칠분만 예약하고, 앱을 열 때마다 채운다.
- 앱 버전에서는 웹 푸시(`push.ts`, 서비스워커)를 쓰지 않는다.

### FR-5 카메라·마이크·사진
- 영상·사진 촬영, 음성 녹음, 앨범 선택이 앱에서 동작해야 한다.
- 각 권한의 사용 이유 문구를 `Info.plist`에 넣는다 (카메라, 마이크, 사진 보관함 읽기, 사진 보관함 저장).
- 권한을 거절했을 때 설정 앱으로 가는 안내를 보여준다.

### FR-6 영상·백업 저장과 공유
- 만든 영상을 사진 앱에 저장하고, 아이폰 공유 시트로 공유할 수 있어야 한다.
- 설정의 백업 내보내기·가져오기가 앱에서 동작해야 한다 (파일 앱·공유 시트 사용).

### FR-7 서버 연결
- AI Worker와 Media Worker(BGM)가 앱의 요청 출처(`capacitor://localhost`)를 허용해야 한다. 허용하지 않으면 AI 연출과 BGM이 막힌다.
- 웹 버전 종료 시점에 GitHub Pages 출처 허용을 뺀다.

### FR-8 웹 버전 종료
- 앱 출시 후 `sage0316.github.io/myhour`는 앱 설치 안내 페이지로 바꾼다.

### FR-9 디자인 리뉴얼
- 캔버스 시안(홈, 오늘, 기록하기 5종, 하루 마감, 아카이브, 설정)을 실제 화면에 반영한다.
- 기능·순서는 지금 코드 그대로 두고 디자인만 바꾼다. 사용자가 확인한 결정(탭 4개 유지, "기록" 용어, 두꺼운 그림자 제거, 본문 고딕·포인트만 손글씨 등)을 따른다.
- 페이월 화면을 새로 디자인한다.

### FR-10 출시용 정리
- 설정의 숨은 테스트 도구는 출시 빌드에서 완전히 뺀다.
- 사용자에게 보이는 개발자용 문구를 없앤다 (예: "알림 서버 배포 후 사용할 수 있어요").

### FR-11 앱스토어 등록 자료
- 앱 아이콘, 실행 화면, 아이폰 스크린샷, 앱 설명, 키워드, 지원 URL, 개인정보처리방침 URL을 준비한다.
- 앱 개인정보 항목(Privacy Nutrition Label)에 AI로 보내는 텍스트·캡션과 RevenueCat 결제 정보를 신고한다.
- 심사용 메모에 테스트 방법(샌드박스 결제)을 적는다.

### FR-12 클라우드 빌드와 배포
- GitHub Actions macOS 러너에서 iOS 앱을 빌드·서명해 TestFlight에 올린다.
- 서명 인증서, 프로비저닝 프로파일, App Store Connect API 키는 GitHub Secrets에만 둔다.
- 빌드는 수동 실행 또는 태그로만 돈다 (`main` 푸시마다 앱스토어에 올라가지 않게).

## 비기능 요구사항

- **보안**: AI 키·RevenueCat 비밀 키·서명 인증서는 앱 코드와 저장소에 넣지 않는다. 기존 Security Baseline 확장을 계속 적용한다.
- **개인정보**: 기록과 미디어는 계속 폰 안에 둔다. AI에는 동의 후 텍스트·캡션만 보낸다. 사진·영상·음성 원본은 어떤 서버에도 보내지 않는다.
- **비용 통제**: 유료 확인 없이는 AI 서버가 OpenAI를 부르지 않는다.
- **호환성**: 기존 저장 키와 데이터 구조를 깨지 않는다 (앱은 새로 시작하지만 같은 코드를 쓴다).
- **품질**: `pnpm check` 통과, 새 로직에는 테스트를 추가한다 (결제 상태 판정, 알림 예약 계산, Worker 권한 확인).
- **접근성**: 44px 안팎 터치 영역, 보이는 포커스, 모션 감소 설정을 지킨다.
- **심사 대응**: 애플 가이드라인 4.2(최소 기능), 3.1.1(인앱결제), 3.1.2(구독 안내), 5.1.1(개인정보)·5.1.2(AI 등 제3자 데이터 공유 동의)를 지킨다. 제출 직전에 최신 가이드라인을 다시 확인한다.

## 사용자가 직접 해야 하는 일

- Apple Developer Program 개인 가입 (연 99달러)
- Small Business Program 신청 (수수료 15%)
- RevenueCat 가입
- App Store Connect에서 앱·상품 등록, 세금·계좌 정보 입력 (화면을 같이 보며 진행)
- GitHub Secrets에 서명·API 키 등록
- Deploy Workers 실행 (Claude의 GitHub 앱은 워크플로 실행 권한이 없음)
