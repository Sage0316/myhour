# 하꾸 프로젝트 맥락

## 제품과 사용자

하꾸(hakku, 하루 꾸미기)는 하루의 짧은 순간을 사진·영상·글로 남기고, 하루가 끝날 때 세로형 회고 영상으로 정리하는 로컬 우선 PWA다. 핵심 사용자는 복잡한 일기 작성보다 빠른 기록과 감성적인 결과물을 원하는 모바일 사용자다.

사용자 노출 이름은 `하꾸/HAKKU`이며 GitHub 저장소, 배포 base path, 기존 저장 키는 호환성을 위해 `myhour`를 유지한다.

## 핵심 경험

1. 오늘의 시간 슬롯에 텍스트와 미디어를 기록한다.
2. 종료 화면에서 분위기, 이모지, BGM을 선택한다.
3. 브라우저에서 720×1280 회고 영상을 생성한다.
4. 완성된 하루를 아카이브하고 백업·복원한다.
5. AI 연출과 Push 알림은 선택 기능이며 보호된 Worker를 통해서만 사용한다.

작동하지 않는 선택지와 마감 후 죽은 상태는 두지 않는다. 모든 옵션은 결과물에 반영되고, 마감 후 흐름은 아카이브로 이어져야 한다.

## 실제 아키텍처

- 프론트엔드: React 19, TypeScript, Vite, PWA
- 상태/도메인: React 어댑터와 도메인·저장소·서비스 경계
- 로컬 데이터: IndexedDB 중심, 설정용 제한적 localStorage
- 미디어: 모든 Blob을 IndexedDB에서 관리하고 참조 정리·용량 검사를 수행
- 영상: 브라우저 생성, 진행률·취소·자원 해제 지원
- AI: 브라우저 직접 키 사용 금지, 동의된 최소 텍스트 DTO를 인증된 Cloudflare Worker로 전송
- Push: 설치 토큰과 소유권 검증이 있는 Worker, 실제 인프라는 KV와 rate-limit binding 사용
- 전달: GitHub Actions 품질 게이트, Pages artifact, Worker preview/production 구분

핵심 기록·영상에는 일반 백엔드가 필요하지 않다. 백엔드는 AI 비밀키 보호와 Push 인증에만 둔다.

## 데이터 모델 원칙

- `id`: 영속 엔터티의 안정적인 식별자
- `slotId`: 사용자가 기록한 시간 구간
- `capturedAt`: 실제 촬영·작성 시각
- `mediaId`: IndexedDB Blob 참조
- 아카이브와 백업은 안정적인 ID를 사용하며 화면 표시 시각을 키로 사용하지 않는다.
- 메타데이터와 Blob 저장은 단계적 쓰기·보상 정리를 적용한다.
- 마이그레이션은 기존 데이터와 저장 키를 보존해야 한다.

## 보안과 개인정보

- Anthropic 등 공급자 키를 클라이언트나 `localStorage`에 저장하지 않는다.
- AI 전송 전 명시적 동의를 받고 이미지·영상 원본은 전송하지 않는다.
- Worker는 Origin, 입력 스키마, 본문 크기, 출력 크기, 토큰 만료, 소유권, 멱등성, 일일 할당량을 검증한다.
- 설치 토큰은 HMAC으로 서명하고 secret은 Worker secret으로만 관리한다.
- 백업 파일은 현재 암호화되지 않으므로 UI와 문서에 이를 명확히 고지한다.

## 접근성·성능 원칙

- 클릭 가능한 일반 요소 대신 실제 `button`과 dialog 의미 구조를 사용한다.
- 키보드 조작, 접근성 이름, focus trap, 닫은 뒤 focus 복귀를 보장한다.
- 길게 누르기만 가능한 삭제 동작을 만들지 않는다.
- 영상 생성 전 저장 용량을 검사하고 메인 스레드 부하·메모리 해제를 관리한다.
- BGM 18곡은 `myhour/public/bgm`에 모두 유지한다. 초기 JavaScript 번들과 서비스워커 install precache에는 포함하지 않고, 선택한 곡의 상대 URL만 지연 로딩하며 runtime cache를 사용한다.

## 배포 제약

- preview와 production의 Worker 자원·secret·KV를 분리한다.
- Pages와 Worker는 버전 또는 동일 artifact 기준으로 롤백 가능해야 한다.
- BGM 라이선스, 실제 모바일 기기, secret/KV/VAPID, 보안 헤더 호스팅이 출시 전 필수 게이트다.
